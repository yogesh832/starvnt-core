## Changes made in this slice

- Replaced the dashboard's all-time raw list ratios with a unique-opportunity cohort calculation. It uses a selectable 30/60/90-day enquiry cohort, excludes the newest 30 days until attribution matures, joins quotes and bookings by opportunity ID, requires a recorded first quote submission transition, and counts only Core-confirmed bookings.
- Added average time to first submitted quote from the first recorded `SUBMITTED` history transition; missing transition history is excluded and zero samples display as insufficient data.
- Added authenticated `/vendor/metrics/first-response`, which measures the earliest vendor message or quote submission per unique opportunity in the same matured 30/60/90-day cohort. It returns only aggregate values and marks capped/incomplete queries unavailable.
- Added the Action Center for actual `NEW` opportunities, `DRAFT` quotes, individual unread customer-message threads with deep links, upcoming confirmed bookings in `NOT_STARTED`/`SERVICE_SCHEDULED`, active `SERVICE_STARTED` bookings, unreplied published STARVNT reviews, and incomplete profile setup. Items are prioritized and show source state and reason. Active-booking actions do not claim the work is late or complete; they tell vendors to submit evidence only after completion. No due dates are manufactured.
- Extended the existing vendor decline action to require an internal reason, store its timestamp and text, and surface reason counts in the selected mature sales cohort. Legacy declines without saved reasons are not guessed.
- Added persistent, vendor-owned goals with a three-active-goal cap and progress from quote transition history or Core booking truth. Response-time goals remain unsupported until lower-is-better units, baseline and target validation are defined.
- Extended the existing `/vendor/financial-truth` summary with due-this-week receivables and distinct settlement-eligible, settlement-hold and settled amounts. A `COMPLETION_VERIFIED` booking is not counted as payout-eligible unless Core records `SETTLEMENT_ELIGIBLE`; no payout-initiated state is invented.
- Added dashboard summaries for published STARVNT reviews, independent operating-readiness dimensions, comparable elapsed-week counts for enquiries, submitted quotes, confirmed bookings and published reviews, and an evidence-based vendor improvement panel. Missing sources show unavailable; no zero-prior-period growth rate is fabricated.
- Reworked the existing vendor-intelligence recommendation service to remove hard-coded venue and traffic claims. Suggestions now cite record evidence and are omitted when the trigger is not present.
- Payment KPI sums now include verified advances from confirmed bookings only. Failed API sources are reported and dependent values display unavailable rather than zero.
- Dashboard activation failures no longer appear as a real 0%-complete profile; readiness/onboarding messages are withheld until the activation source is available. Quote submission now starts with a blank vendor price rather than copying the customer's budget, preserves the actual service name, validates amounts, keeps the dialog open on API failure, and displays the error for retry. Dashboard refreshes now discard older overlapping poll/focus/retry responses so an older snapshot cannot overwrite a newer one. A last-complete-refresh timestamp and stale-data label make dashboard freshness visible.
- Analytics now loads the complete vendor-owned enquiry, quote and booking collections and computes enquiry-to-quote and quote-to-booking rates from distinct linked records. Unrelated counts no longer produce conversion rates above 100%; a unit test covers drafts, duplicates, cancellations and unlinked records.
- The QA vendor seeder now creates capability and coverage records against each service ID, so each seeded service has the configuration the service editor and matcher expect. The QA harness uses a configurable loopback API base and defaults to port 4410 to avoid silently testing the shared 4100 server.
- Server startup output reports the database names parsed from its configured Mongo URIs instead of hard-coded database labels. This makes an incorrect local test-server target easier to detect without logging connection credentials.
- Added a vendor-scoped `VendorBusinessGoal` collection and `/api/vendor/goals` CRUD routes. No existing goal data needs backfill. The model declares indexes; verify production's Mongoose `autoIndex` policy or create indexes through the standard database migration process.

## Requirements still open

The implementation does not yet satisfy the full supplied master specification. In particular:

- A complete dashboard health snapshot for each specified metric, with server-side period filtering, stable response contracts and metric freshness.
- Qualification rules and reasons for legacy declines remain unavailable or undefined.
- The Action Center can now surface active bookings for review, while actual completion evidence submission remains in the booking workflow. Post-event document prompts and vendor-safe dispute handling remain open because the current product contracts do not define vendor actions, ownership, visibility, or timing for those cases.
- Full weekly operational performance, including week-over-week response-time comparisons and completed tasks, plus category approval/document status dimensions not currently provided by the activation API.
- Goal edit and status lifecycle browser E2E, multi-process active-limit concurrency proof, and a long-term retention policy for soft-deleted goals.
- Recommendation dismissal/feedback and category-specific portfolio/service guidance are not represented in the current product contracts.
- Unified notification event coverage, idempotency, and preference/channel verification.
- Quote, booking-evidence, portfolio, service-capacity, payment-webhook, review-eligibility and messaging acceptance journeys identified in `docs/vendor-os-acceptance-audit-2026-10-27.md`.
- Broader security review across every vendor route, nested object ID, attachment and role; authenticated browser E2E and production-role checks. Targeted quote, booking, enquiry, review, message and goal isolation tests now pass.
- Reconciliation against approved, non-sensitive test vendor records; no production dataset was accessed for this change.
- Desktop/mobile screenshots, accessibility inspection, real-device testing, load/performance measurements and deployment/rollback proof.
