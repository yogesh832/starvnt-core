# Aura commercial authority and context — 17 November 2026

Development-only guard changes using ordinary quotations, existing activation/schedule/policy checks and current contact permissions. No Proposal Studio, money movement, identity decision, legal acceptance or campaign publication added.

- Aura revision proposals bind exact owned quote ID/reference, commercial version and record version from server context. Raw model version fields do not determine authority. Missing/unknown records no longer fall back to the first quote; ambiguous name matches do not choose a record. User confirmation summaries use the canonical source identity.
- Execution rechecks state, owner, both versions and pending payment before mutation. Existing payment attempts cannot be reset. Quotes with additional equipment/setup/other charges require the full quote editor instead of silently dropping fees. Allowed simple revisions use canonical itemized validation and record a new immutable commercial snapshot/archive, preserving exact cents.
- Creation requires a current open owned enquiry with the same recipient, service, event date and update timestamp that was proposed. Expired enquiries and changed/cross-vendor context reject before creation. Source location and service come from the owned enquiry. The model cannot choose an arbitrary customer or default service or merge a name/phone into another identity.
- Unsupported authority-bearing action kinds explicitly return a controlled denial rather than leaving a model's success claim untreated. Tests cover money approval, bank/PAN verification, agreement acceptance, campaign publication, customer merging and refunds.
- Aura quotes/enquiries now use the same current privacy projection as the normal Vendor APIs before entering model context. Exact pre-booking customer identity is withheld according to that policy. Business profile and onboarding percentages have separate source denominators. Current model context includes canonical quote/enquiry versions needed for confirmation.
- Shared exact-price validation rejects values outside safe integer paise precision. This is a representation limit, not a new commercial cap or financial policy.

Verification: 35 targeted tests passed across booking-workflow.test.js, vendor-main17-integrity.test.js and vendor-aura-capability.test.js. Evidence: tmp/vendor-main17-implementation/aura-guard-regressions.log. Cases cover positive exact-cent Aura revision and preserved archive, payment/stale denial, foreign/changed/expired enquiry denial, unsupported authority, model-supplied version denial, context privacy and existing capability confirmation regressions. Synthetic MongoMemoryServer fixtures and .env.test.example only; no live model/provider acceptance claimed. Full backend regression follows this commit.

Limits: this does not finish all Aura operational-command versioning, creation-request recovery, model/prompt/cost/latency evaluation, provider fallback, full enquiry admission/invitation/ranking or native acceptance. Those tracker rows remain partial/open. Existing own-source/window limits may require opening the relevant enquiry/quote before proposing an action; no hidden broader search or identity matching is performed.

Migration/rollback: additive context metadata, runtime guards and no data migration. Already-pending pre-upgrade actions without current source versions require a fresh proposal/confirmation. Preserve commercial/payment archives and source privacy on rollback. Do not bypass pending-payment or safe-currency guards to restore an old assistant behavior. No production deployment performed by this task.
