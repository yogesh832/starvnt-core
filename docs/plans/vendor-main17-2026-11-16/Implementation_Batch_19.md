# Owned enquiry creation and honest quote evidence — 17 November 2026

Partial V55.03/V60/V66 continuation using the existing vendor-owned Opportunity reference. The specification requires an enquiry ID on quotations and stops initial responses after invitation expiry. New creation now requires a real owned enquiry, its customer and its requested vendor service. Declined/expired/unknown source states and elapsed/invalid recorded deadlines reject new creation. A committed request key is recovered before these new-source checks, so expiry cannot cause another quote to be created on retry. Stored legacy quotes, their reads and existing revision paths are not rewritten or deleted. This does not decide the pending central-enquiry storage/adapter ownership or atomic five-slot admission design.

The enquiry API now reports actual owned quote presence/count and a single status only when there is one record. It does not label an unsent draft or a general enquiry response as a submitted quotation, choose a status from ambiguous multiple quotes, or reopen a declined/expired enquiry based on historical quotes. Quote-source lookup failure propagates instead of becoming an empty array. Web/native actions route existing drafts/offers to quote review instead of posting another initial record. Unknown quote evidence also directs review rather than inventing absence.

Web Enquiries separates load errors from genuine empty results, supports retry, retains stale-source disclosure and guards response effects after unmount/retry. Mutation errors have error presentation, including inside an open quote modal; pending submissions disable edits/close/cancel. They no longer use the green success check. No Customer screen changed.
