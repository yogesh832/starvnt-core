# Recoverable quote creation effects — 17 November 2026

Partial V64.04/V67.01 continuation of Batch17. A newly submitted keyed quote now saves an immutable hash-bound creation-effect snapshot and pending marker in the same document write as its commercial evidence. If the process stops before publishing its outbox record, the existing enabled outbox worker discovers the pending source and republishes that reference. No new worker or channel is activated. Queue scans remain bounded and rotate failed entries so an invalid oldest record cannot indefinitely starve newer work.

The registered handler derives vendor/customer/enquiry/version/amount from stored quote evidence, not event-supplied prices or authority. It marks only new/viewed enquiries responded, preserves expired/closed enquiry states, and skips stale new-offer messages when the quote has already advanced to another state/version. Quote-triggered processing selects its exact outbox event, so it cannot run an unrelated pending payment event. Event identity/type/aggregate validation prevents a colliding key from redirecting that processing. Missing/inconsistent evidence remains an explicit failure; it does not manufacture a success.

The existing message service has an opt-in strict persistence path. It propagates required in-app write failures to the outbox, emits only fixed safe error codes there, uses a private canonical context key/partial unique index for first-thread races and an atomic event-key append for repeated messages/unread counts. Blocked conversations and ambiguous duplicate legacy contexts require review. Ordinary chat callers retain their existing contract. This uses the existing in-app notification and consent/preference checks; it neither adds nor guarantees external provider delivery. Customer quote-message recognition remains compatible through the existing quote type/prefix and review destination; no Customer screen changed.
