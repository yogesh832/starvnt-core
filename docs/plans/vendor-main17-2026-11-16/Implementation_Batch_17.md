# Quote creation request recovery — 17 November 2026

Partial V64.02/V45.04 implementation through the existing quotation model/API/service. Optional creation commands carry a bounded request key and a canonical hash of the actor, vendor and normalized intent. A partial unique vendor/key index prevents simultaneous retries from creating several records. The same intent recovers the saved quote; a changed actor/content under that key returns a controlled conflict. Legacy calls without a key retain their existing contract. Command metadata is immutable, excluded from ordinary queries/JSON and stripped from both masked and authorized-contact projections.

Both web quote forms and native creation retain a stable key for the open form. Aura uses the pending confirmation key and recovers an existing owned quote before rechecking an enquiry that the first successful execution may already have marked responded. A later expired enquiry is not reopened by recovery. Confirmation copy distinguishes recovery from a new send and directs the vendor to the current saved version; it does not repeat an outdated amount from the original pending action.

Recovery does not repeat the creation-side opportunity/notification effects, avoiding an old request changing later source state or reannouncing a revised quote as newly created. A crash after saving but before those original effects still needs the broader outbox/reconciliation work in V64.04. This batch protects the quote record; it does not claim a transaction spanning databases, exactly-once external delivery, complete creation-effect recovery, or request persistence after closing/reopening the form, browser refresh or app restart. Quote revisions, enquiry/invitation/selection command coverage remain open.
