# Native external booking workspace — 17 November 2026

Development implementation on vendor-dev. No production writes, campaigns, provider transactions or live document upload were performed.

The existing native Vendor workspace now links External bookings. It uses the existing authenticated API for source/lifecycle filtering, bounded pagination, owned detail, lifecycle transitions, reported receipt/refund entries, linked evidence, private document upload/download and immutable payment/booking history. Add/reschedule continues through the existing calendar; no parallel booking engine was created. Shared backend/web lifecycle/source/document definitions are reused through typed declarations. Cancellation defaults the money form to refunds, and a closed record with no refundable reported balance does not offer a money entry. Native local date/time validation rejects invalid or normalized calendar dates.

Uncertain-write recovery preserves the original request key AND original revision after a lost response, even if data refreshes. Different money details cannot replace an unresolved action; the explicit Retry previous action control reconciles the original request first. Known 4xx rejections permit correction. Upload retries preserve the chosen file's request key. Existing backend owner checks, signed private storage grants, replay checks, exact cents, refund limits, schedule leases and actor history remain the authority. These screens never represent vendor reports as captured provider money or Core booking truth.

The shared mobile resource helper now records last successful sync for the specific API/path and retains that timestamp on failed refresh. The shared Page exposes this time and marks the current source unavailable on error; it retains the existing error/retry and hides ordinary failed content rather than inventing empty counts. A changed source path clears the previous path's sync metadata. Composite widgets still require their independent source-status acceptance; V10.02 remains partial.
