# Private verification document access — 17 November 2026

Development implementation; no production records, legacy storage objects or provider verification decisions were automatically corrected. Existing independent verification and activation policies remain separate.

## Implemented behavior

- New Vendor verification files are stored as a non-selected binary field in the existing VendorDocument collection, with MIME, exact size, digest, uploader and time. The owner upload endpoint accepts bounded supported PDF/JPEG/PNG/WebP contents with signature checks, not arbitrary remote URLs. Full bytes/private URLs are removed from ordinary document responses. PAN/GST/bank/ID document numbers and known identity text are masked without corrupting technical IDs or integrity hashes.
- Owner content reads require the current authenticated vendor and exact owned document. Admin reads require vendors.read plus the new vendorIdentity.readSensitive permission, or the existing Super Admin bypass. No role preset automatically receives the new permission. Reads verify content integrity and persist an access audit before returning non-cacheable, nosniff binary data with a generic filename. No public URL or proxy fetch of untrusted URLs is introduced.
- Legacy inline bytes remain privately readable through the audited endpoint without rewriting records. Legacy external/public files are explicitly flagged for authorized privacy migration; their URLs are not exposed or silently fetched. Already-known external URLs cannot be revoked by this code change and require the approved migration/retention process. This is not a claim of completed production privacy remediation.
- The existing Vendor web upload now reads and stores PDF bytes, fixing its prior success-without-PDF-content behavior. Its explicit preview fetches an authenticated Blob and revokes it when the modal closes. Vendor/Admin native clients use the private endpoint rather than public media upload/open links; Admin web has an explicit private evidence download. PNG/WebP native copies retain their correct extensions. Metadata-only provider verification records are distinguished from actual files.
- PAN/GST provider lookup records cannot overwrite or authenticate an uploaded file. New provider verification upserts target metadata-only records for the exact identity number; uploaded proof remains separately reviewed. File-size placeholders are no longer fabricated.
- Document decisions now require an exact document, explicit boolean, review reason and current version. Private evidence approval requires sensitive access and the same actor's audited file read. Version-controlled documents retain append-only review history and record an Admin decision audit. The table-level shortcut opens the KYC panel instead of approving an arbitrary pending record. PAN/GST file review cannot override unresolved provider/name verification; D04's authorized uncertain-name policy remains a real dependency, not a fabricated approval path.

## Migration, rollback and remaining decisions

Additive binary/metadata/review fields and an explicit sensitive permission. No automatic legacy backfill, public-object deletion, identity relabel or historical financial change. Rehearse BSON document size, large-file/record throughput, retention, deletion/hold policy, existing public-object inventory, encryption/backup/restore and role assignment before release. The existing overall application JSON-body limit is not comprehensively remediated by this endpoint's file checks. Existing document deletion/retention policy is not claimed complete.

Rollback must preserve private bytes and review/access evidence, keep ordinary API projections safe and retain a compatible authenticated retrieval path; reverting to inline private image data in ordinary JSON would reopen the original exposure. Coordinate both Vendor clients and Admin permissions. This task has not deployed these changes to production or claimed legal/provider acceptance.
