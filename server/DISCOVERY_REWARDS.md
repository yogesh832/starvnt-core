# Discovery and vendor rewards

## Customer tab

`/customer/discovery` uses the existing location search or optional browser GPS; customers explicitly confirm a point and a 25/50/75/100 km radius. The feed queries a 2dsphere index and returns only an opaque token, allowed category/style, media type and approximate distance. It never returns a vendor ID, portfolio ID, exact coordinates, original URL or contact information. The media endpoint rechecks approval and the original portfolio's current public status and responds with `no-store`. Withdrawal stops subsequent media requests. A browser that already downloaded media cannot be made to forget that copy.

Customers can save an inspiration, filter similar categories, open Aura+ with a generic category/style prompt, or start the existing event planning and enquiry flow with editable inspiration details. These actions do not confirm a booking. Optional in-app discovery notifications require a selected location, explicit notification opt-in and active STARVNT personalization consent. Push to a registered mobile device requires a separate discovery push opt-in and the device push preference. Before each push delivery, the queue rechecks personalization permission, discovery opt-ins, category, current radius, project approval and portfolio visibility. Older discovery notifications without enough context fail closed. Mobile push currently opens the Updates screen; the nearby inspiration tab is available on the customer web portal. The worker uses the existing notification service, current radius/category, quiet hours, a seven-day frequency limit and per-customer/project deduplication. It sends generic text without vendor identity. Interaction evidence is recorded only with personalization permission, deduplicated per day, excluded from analytics after permission withdrawal, and removed during account deletion. A proposal click is an intent, not a booking conversion. With personalization permission, an event created from an inspiration can be attributed; admin analytics separately count later related enquiries and confirmed Core bookings for up to 500 recent attributed events, reporting truncation.

## Vendor and admin tabs

`/vendor/discovery-rewards` lets an owner submit a separately uploaded image or MP4 from an owned public portfolio item, state usage permission, choose category/style and give the project's coordinates. Uploads are limited to 8 MB, 10 attempts per ten minutes and 50 non-withdrawn submissions per vendor; request keys make retries idempotent and reject changed content. Images are re-encoded with sharp; MP4 clips are re-encoded to at most 30 seconds with metadata and audio removed. Processed bytes are stored in MongoDB, separately from the original portfolio. The discovery-review permission allows admins to inspect the entire sanitized media and approve only after explicitly checking rights and visible identities, logos, watermarks and contacts; admins can suspend an approved project. This is human review, not automated detection. Vendor withdrawal revokes access without deleting the original portfolio. Owners can permanently remove a withdrawn discovery copy from the vendor tab after confirmation. Optional automatic cleanup is disabled until DISCOVERY_WITHDRAWN_RETENTION_DAYS is configured (1–3650 days); it removes processed bytes only after a recorded withdrawal date and appends an audit entry. Original portfolio assets and audit records remain. Legacy withdrawn records without a recorded date require separate review. Backups remain subject to the deployment backup policy.

The same vendor tab shows evidence-backed milestones, level, XP history, optional Core-completion challenges and non-cash benefit requests. Admins can create versioned point and level-threshold policies, challenges and benefits, review requests, and reverse awards with reasons. A milestone awards once per vendor; current evidence is rechecked, missing evidence reverses earned XP, and manual reversal is not automatically re-awarded. Challenges are limited to seven days and 50 XP and require a Core completion verified within the challenge period; a Core booking cannot earn multiple challenge awards. Earned awards produce deduplicated in-app vendor achievement notifications when the wallet is refreshed. Challenge and milestone XP are separate from redeemable credits; cash credits are not implemented. Benefit requests and approvals recheck current matching eligibility and XP. No reward changes verification, public rating or matching authority.

## Operational boundaries

- Production must install an FFmpeg executable with libx264 and set `DISCOVERY_FFMPEG_PATH` if it is not on PATH. Video input is temporarily written under the OS temporary directory for seekable MP4 processing and removed afterward; an unclean process crash can leave a temporary input for operations to clear. Local tests use the host FFmpeg; deployment availability is not verified.
- Create and verify the new MongoDB unique and geospatial indexes before exposing the tabs. No production data migration or deployment was performed. Reviewers need `discovery.review`; reward policy and decisions need `growth.read`/`growth.manage`; analytics requires `analytics.read`.
- Set an XP policy and create benefits/challenges in admin before any configured reward or offer appears. There are no promised leads, automatic monetary credits, or existing financial redemption integrations.
- Current discovery is capped at 50 results and 50 active submissions per vendor. The experience is image/MP4 only, silent on video, and requires explicit manual moderation. Anonymous sharing links and consented daily-deduplicated sharing intents are available; they do not prove delivery to another person. Automated visible-identity detection is not implemented. In-app notifications and separately opted-in mobile push are available; the proposal path prepares the existing event workflow rather than automatically sending an enquiry.

## Workspace routing note (2026-11-04)

The current web App routes `/vendor/*` to the customer portal and no longer mounts VendorPortal. The vendor deletion control is implemented in the existing vendor screen source, but is not reachable through this customer-only entrypoint. Vendor backend ownership checks remain enforced. Customer sharing and discovery settings remain reachable. Mobile discovery push currently opens Updates, rather than a native Nearby Inspiration screen. Live provider delivery has not been verified.
